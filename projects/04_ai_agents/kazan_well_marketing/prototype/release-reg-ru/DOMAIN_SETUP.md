## Что проверить до публикации на REG.RU
Ключевой момент: сайт теперь подготовлен в двух режимах:
- локально форма может работать через `server.py` и `POST /api/lead`
- на обычном shared hosting форма может работать через `api/lead.php`

Для бесплатного REG.RU это практичнее, потому что PHP на shared hosting встречается заметно чаще, чем возможность запустить отдельный Python-процесс.

Перед публикацией проверьте:
- поддерживает ли тариф выполнение PHP-скриптов
- доступна ли запись в папку `data/`
- можно ли положить файл `api/config.php` с настройками Telegram

## Практический план для REG.RU
1. В панели REG.RU открыть услугу хостинга.
2. Проверить, что на тарифе исполняется PHP.
3. Добавить домен `аквастрой-казань.рф` в список сайтов хостинга.
4. В качестве корневой папки сайта указать каталог, куда будут загружены файлы из `prototype/`.
5. Загрузить содержимое папки `prototype/` на хостинг:
   - `index.html`
   - остальные `*.html`
   - `style.css`, `app.js`
   - папку `api/`
   - папку `data/`
   - favicon-файлы
   - `robots.txt`
   - `sitemap.xml`
6. На хостинге создать файл `api/config.php` по образцу `api/config.php.example`.
7. Записать в `api/config.php` реальные значения:
   - `site_name`
   - `telegram_bot_token`
   - `telegram_chat_id`
8. Проверить права на запись для папки `data/`.
9. В панели домена REG.RU направить домен на этот хостинг.
10. Выпустить и включить SSL-сертификат в REG.RU.
11. Проверить открытие сайта по адресу `https://аквастрой-казань.рф`.
12. Отдельно отправить тестовую заявку через форму.

## DNS для REG.RU
На практике возможны два сценария, в зависимости от того, как именно REG.RU ведёт ваш хостинг:
- домен делегируется на NS-серверы REG.RU и затем привязывается к хостингу внутри панели;
- или для домена задаются `A`/`CNAME` записи на значения, которые показывает REG.RU в карточке услуги.

Итог: точные DNS-значения нужно брать именно из панели REG.RU, потому что они зависят от конкретного тарифа и типа размещения.

## Рекомендуемая структура публикации
