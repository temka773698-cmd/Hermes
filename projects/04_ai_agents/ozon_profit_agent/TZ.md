# ТЗ: Ozon Profit & Growth Agent — версия 1 «Антиубыток»

## 1. Цель проекта

Создать первого рабочего агента для продавца на Ozon, который ежедневно контролирует товары, цены, акции и прибыльность, чтобы продавец не уходил в убыток из-за скидок, комиссий, логистики, рекламы или ошибочных цен.

Первая версия НЕ должна автоматически менять цены и карточки без подтверждения. Главная задача MVP — безопасный контроль, расчёт и рекомендации.

---

## 2. Короткое описание продукта

**Ozon Profit & Growth Agent** — это помощник продавца Ozon, который:

- получает данные по товарам из Ozon;
- берёт себестоимость и бизнес-правила из таблицы;
- считает минимальную безопасную цену;
- определяет товары в убытке или с низкой маржой;
- проверяет влияние акций;
- формирует ежедневный отчёт;
- отправляет предупреждения в Telegram;
- предлагает действия: поднять цену, выйти из акции, проверить себестоимость, не участвовать в акции.

---

## 3. Главный принцип безопасности

Агент сначала работает в режиме:

> **Читает данные → считает → предупреждает → предлагает действие.**

Запрещено в первой версии:

- автоматически менять цены;
- автоматически добавлять товары в акции;
- автоматически удалять товары из акций;
- автоматически менять SEO и карточки;
- автоматически менять изображения;
- принимать решения без порога безопасности.

---

## 4. MVP: первая версия

Название MVP:

> **Ozon-антиубыток**

Главная польза:

> Каждый день показывать, какие товары продаются в минус или близко к минусу, и что с ними делать.

## 5. Пользовательские сценарии

### Сценарий 1. Ежедневный отчёт

Каждое утро агент отправляет отчёт:

```text
Ежедневный отчёт Ozon

Всего товаров: 120
В норме: 93
Низкая прибыль: 18
В убытке: 9

Главные проблемы:
1. Товар A — цена ниже безопасной на 350 ₽
2. Товар B — акция делает продажу убыточной
3. Товар C — не указана себестоимость
```

### Сценарий 2. Товар ушёл в минус

Агент отправляет предупреждение:

```text
⚠️ Товар уходит в убыток

Товар: Насос X
Артикул: PUMP-001
SKU Ozon: 123456789
Текущая цена: 4 490 ₽
Минимальная безопасная цена: 4 890 ₽
Отклонение: -400 ₽
Причина: акция / скидка / низкая цена

Рекомендация:
- поднять цену минимум до 4 890 ₽
- или выйти из акции
```

### Сценарий 3. Товар без себестоимости

Если по товару нет закупочной цены, агент не должен гадать.

```text
⚠️ Не могу посчитать прибыльность

Товар: Фильтр Y
Артикул: FILTER-002
Причина: не указана себестоимость

Что нужно сделать:
- заполнить закупочную цену
- указать упаковку
- указать минимальную прибыль
```

### Сценарий 4. Проверка акции

Агент анализирует участие товара в акции:

```text
Акция: Скидка 15%
Товар: Насос X
Цена после скидки: 5 100 ₽
Минимальная безопасная цена: 5 400 ₽

Решение: участвовать нельзя, будет убыток.
```

## 6. Какие данные нужны

### 6.1. Данные из Ozon

Для каждого товара нужно получить:

- название товара;
- offer_id / артикул продавца;
- product_id;
- sku;
- текущая цена;
- цена до скидки;
- маркетинговая цена, если есть;
- остатки;
- статус товара;
- комиссии, если доступны через API;
- участие в акциях, если доступно;
- продажи за период, если доступно;
- расходы на продвижение, если доступно.

### 6.2. Данные от продавца

Эти данные лучше хранить в Google Sheets, Excel или локальной таблице CSV.

Колонки:

```text
offer_id
Название
Закупочная цена
Упаковка
Дополнительные расходы
Налог, %
Минимальная прибыль, ₽
Минимальная маржа, %
Минимальная разрешённая цена
Комментарий
Можно менять цену автоматически: да/нет
Можно участвовать в акциях: да/нет
Товар важный: да/нет
```

## 7. Формула расчёта прибыльности

Базовая формула:

```text
Прибыль = Цена продажи - Себестоимость - Расходы Ozon - Упаковка - Налог - Реклама - Прочие расходы
```

Минимальная безопасная цена:

```text
Минимальная безопасная цена = Себестоимость + Расходы Ozon + Упаковка + Налог + Реклама + Минимальная прибыль
```

Если точные комиссии Ozon пока не подтягиваются, в MVP можно использовать приближённые значения из таблицы.

---

## 8. Статусы товара

Агент должен присваивать каждому товару один из статусов:

### OK

Товар продаётся с нормальной прибылью.

Условие:

```text
Текущая цена >= Минимальная безопасная цена + запас
```

### LOW_MARGIN

Товар не в убытке, но прибыль слишком маленькая.

Условие:

```text
Текущая цена >= Минимальная безопасная цена
но маржа ниже желаемой
```

### LOSS

Товар уходит в убыток или ниже минимальной безопасной цены.

Условие:

```text
Текущая цена < Минимальная безопасная цена
```

### NO_COST_DATA

Не хватает данных для расчёта.

Условие:

```text
Нет себестоимости или обязательных расходов
```

### CHECK_REQUIRED

Есть подозрительные данные.

Примеры:

- цена резко изменилась;
- себестоимость выше цены;
- комиссия не найдена;
- товар участвует в акции, но цена не совпадает с ожиданием.

---

## 9. Рекомендации агента

Агент должен выдавать не просто статус, а понятное действие.

Варианты рекомендаций:

- `Поднять цену до X ₽`;
- `Выйти из акции`;
- `Не добавлять в акцию`;
- `Можно участвовать в акции`;
- `Заполнить себестоимость`;
- `Проверить комиссию Ozon`;
- `Проверить расходы на рекламу`;
- `Не трогать товар`;
- `Требуется ручная проверка`.

---

## 10. Telegram-уведомления

### 10.1. Ежедневный отчёт

Отправляется 1 раз в день.

Содержит:

- общее количество товаров;
- количество товаров в норме;
- количество товаров с низкой прибылью;
- количество товаров в убытке;
- количество товаров без данных;
- топ-10 самых опасных товаров;
- краткие рекомендации.

### 10.2. Срочное предупреждение

Отправляется сразу, если:

- товар стал убыточным;
- товар добавлен в невыгодную акцию;
- цена упала ниже минимальной безопасной;
- нет себестоимости по товару с продажами.

## 12. Что НЕ входит в первую версию

В MVP не делаем:

- полноценную веб-панель с авторизацией;
- мультиаккаунты для многих продавцов;
- автоматическую смену цен;
- автоматическое участие в акциях;
- автоматическую генерацию картинок;

- сложную аналитику конкурентов;
- прогнозирование спроса;
- рекламный биддинг.

## 14. Первая версия бизнес-правил

Правила по умолчанию:

```text
Не считать товар безопасным, если прибыль меньше 300 ₽.
Не считать товар безопасным, если маржа меньше 15%.
Если нет себестоимости — не давать рекомендации по цене.
Если цена ниже безопасной — статус LOSS.
Если товар в акции и цена ниже безопасной — рекомендовать выйти из акции.
Если товар важный — только предупреждать, не предлагать автоматическое действие.
```

Эти правила должны настраиваться в таблице или конфиге.

---

## 15. Критерии готовности MVP

MVP считается готовым, если:

- можно загрузить таблицу себестоимости;
- можно получить или загрузить список товаров Ozon;
- по каждому товару считается прибыль;
- каждому товару присваивается статус;
- формируется CSV-отчёт;
- формируется короткий текстовый отчёт;
- Telegram получает ежедневный отчёт;
- товары без себестоимости не считаются наугад;
- агент не предлагает убыточные действия;
- все расчёты можно проверить вручную.

## 17. Главный риск проекта

Главный риск — неправильная экономика.

Если агент плохо считает комиссии, логистику, скидки или себестоимость, он может давать вредные рекомендации.

Поэтому первая версия должна быть максимально скучной, но точной:

> сначала расчёты и контроль убытков, потом автоматизация.

---

Сделать локальный прототип без Ozon API:

3. Написать калькулятор прибыли.
4. Получить отчёт по статусам.
5. Проверить вручную 2–3 товара.

После этого подключать Ozon API.
